\begin{abstract}
Water scarcity in rural agricultural landscapes necessitates scientific, data-driven planning for surface rainwater harvesting structures. This report presents the technical design, mathematical foundation, system architecture, multi-VM infrastructure deployment, and verification results of the \textbf{AI-based Village Pond Planning System (JalSetu Studio)}. The system integrates satellite map visualization, KML/KMZ contour terrain analysis, automated boundary geocoding, and historical rainfall integration to recommend optimal $K$ candidate pond excavation sites. A high-performance web architecture was constructed featuring a vanilla JavaScript/Leaflet GIS interactive frontend, an Nginx load balancer operating across three FastAPI backend VM worker nodes (\texttt{172.17.0.19}, \texttt{172.17.0.20}, \texttt{172.17.0.21}), and a self-contained GitHub Actions CI/CD pipeline publishing containerized Docker images to GitHub Container Registry (\texttt{ghcr.io}). Hydrological modeling leverages coupled USDA Soil Conservation Service Curve Number (SCS-CN) runoff yield modeling, D8 steepest-descent flow direction routing, and recursive upstream Breadth-First Search (BFS) watershed catchment delineation. Empirical testing demonstrates $100\%$ pass rates across the automated 11-suite backend API test matrix. The complete application repository is maintained at \url{https://github.com/Aj1359/AI-Pond-Planner.git}, with a live demonstration video available at \url{https://youtu.be/zH_eiQb3qNg} and live public deployment hosted at \url{http://10.1.75.51:4217/ui/}.
\end{abstract}

\section{Introduction}
\label{sec:intro}
Rural agricultural security in arid and semi-arid regions relies heavily on community and farm ponds that capture seasonal monsoon runoff for dry-season irrigation, groundwater recharge, and livestock consumption. Traditional pond site selection relies primarily on visual inspection or local intuition, often leading to sub-optimal placement in flat zones with insufficient catchment yield, excessive evaporation losses, or embankment instability.

This report documents the technical design, mathematical formulation, software implementation, and multi-VM infrastructure deployment of the \textbf{AI-based Village Pond Planning System (JalSetu Studio)}. The system provides an interactive, browser-based decision support system for village administrators, agricultural officers, and rural engineering teams.

\subsection{Motivation}
Manual site selection presents several engineering challenges:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Micro-Topographic Complexity}: Identifying natural terrain depressions and flow pathways across agricultural land is difficult without digital elevation models (DEMs).
    \item \textbf{Data Fragmentation}: Historical rainfall records, soil retention coefficients, and elevation datasets are isolated across different agency databases.
    \item \textbf{Civil Engineering Calculations}: Manual calculation of slope stability, runoff yield, and 3D excavation volumes requires specialized GIS software inaccessible to local village panchayats.
\end{enumerate}
An automated web GIS tool empowers non-expert stakeholders to select land areas interactively and receive instantaneous, mathematically sound siting and sizing recommendations.

\subsection{Scope of the Project}
The system scope includes:
\begin{itemize}[leftmargin=*]
    \item Interactive satellite/street map display with OpenStreetMap Nominatim village search and automated boundary polygon fetching.
    \item Freehand lasso, rectangle, and circle drawing tools to delineate custom land sub-areas.
    \item Single-step KML/KMZ contour map upload analysis endpoint (\texttt{/analyzeContour}) with direct front-and-center map polyline rendering.
    \item Automated fetching/interpolation of DEM elevation matrices and historical 10-year monthly precipitation records (Open-Meteo API).
    \item D8 steepest-descent flow direction calculation and recursive upstream BFS catchment delineation.
    \item SCS-CN surface runoff volume estimation and 3D inverted trapezoidal frustum pond sizing ($1.5:1$ side slope, $+0.5\text{ m}$ freeboard).
    \item Nginx load balancing across three backend worker instances with two-level caching.
    \item GitHub Actions CI/CD workflow for automated linting, unit testing, and Docker container publishing.
\end{itemize}
\textbf{Out of Scope}: Detailed soil mechanical cohesion/shear strength laboratory testing, structural concrete spillway design, and real-time land ownership ledger verification.

\section{Methodology}
\label{sec:methodology}

\subsection{Terrain and Elevation Analysis}
Terrain elevation is modeled as a discrete 2D grid matrix $Z \in \mathbb{R}^{M \times N}$. For user-selected bounding boxes or KML contour uploads, elevation values are obtained via SRTM 30m raster tiles or interpolated from KML polyline coordinates using Delaunay triangulation. For arbitrary geographic coordinates $(\text{lat}, \text{lon})$, elevation estimation is performed via bilinear interpolation from grid cell coordinates $(x_0, y_0), (x_1, y_1)$:
\begin{equation}
z(x, y) = \frac{(x_1 - x)(y_1 - y)}{(x_1 - x_0)(y_1 - y_0)} z_{00} + \frac{(x - x_0)(y_1 - y)}{(x_1 - x_0)(y_1 - y_0)} z_{10} + \frac{(x_1 - x)(y - y_0)}{(x_1 - x_0)(y_1 - y_0)} z_{01} + \frac{(x - x_0)(y - y_0)}{(x_1 - x_0)(y_1 - y_0)} z_{11}
\end{equation}

Local ground slope percentage $S_{i,j}$ is derived using 3x3 Sobel spatial gradient filters:
\begin{equation}
G_x = \frac{\partial z}{\partial x}, \quad G_y = \frac{\partial z}{\partial y}, \quad S_{i,j} = \sqrt{G_x^2 + G_y^2} \times 100\%
\end{equation}
Candidate pour-points filter for local elevation minima ($S_{i,j} \le 6.0\%$). If steep terrain yields 0 points, a graceful fallback orders cells by gentlest available slope.

\subsection{Catchment Area Delineation}
The hydrological contributing basin for a pour-point $(r_0, c_0)$ is computed using D8 steepest descent flow routing. Flow direction $D(r,c) \in \{1, 2, 4, 8, 16, 32, 64, 128\}$ assigns direction to the steepest neighbor:
\begin{equation}
\Delta z_k = \frac{z(r, c) - z(r + \Delta r_k, c + \Delta c_k)}{d_k}
\end{equation}
Catchment delineation executes recursive upstream Breadth-First Search (BFS) starting from $(r_0, c_0)$:
\begin{equation}
\text{Catchment}(r_0, c_0) = \left\{ (r, c) \;\middle|\; \text{Route}_D(r, c) \to (r_0, c_0) \right\}
\end{equation}
Total catchment area $A_{\text{catchment}}$ (in hectares) is the sum of grid cell areas within the delineated polygon boundary.

\subsection{Rainfall Integration \& Runoff Yield}
Historical 10-year monthly precipitation time series are queried from Open-Meteo for the centroid location. Annual rainfall $P$ (mm) is aggregated. Surface runoff $Q$ (mm) is modeled via USDA SCS-CN:
\begin{equation}
S = \frac{25400}{CN} - 254 \quad (\text{Potential Retention in mm}), \quad I_a = 0.2 \cdot S \quad (\text{Initial Abstraction})
\end{equation}
\begin{equation}
Q = \frac{(P - I_a)^2}{P - I_a + S} \quad (\text{if } P > I_a)
\end{equation}
Annual harvestable runoff volume $V_{\text{runoff}} = Q \cdot A_{\text{catchment}} \cdot 10 \quad (\text{m}^3)$.

Pond dimensions are optimized using a 3D inverted trapezoidal frustum geometry ($1.5:1$ side slope, $+0.5\text{ m}$ freeboard):
\begin{equation}
V_{\text{pond}} = \frac{d}{3} \left( A_{\text{top}} + A_{\text{bottom}} + \sqrt{A_{\text{top}} \cdot A_{\text{bottom}}} \right)
\end{equation}

The three most significant engineering design decisions were:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Nginx Load Balancer with \texttt{least\_conn} Routing}: DEM grid interpolation and D8 flow routing are computationally heavy matrix operations.     \item \textbf{Decoupled Modular Monolith Architecture}: Choosing a modular monolith over separate microservices eliminated inter-service network latency while allowing clean code separation between geocoding, terrain modeling, and API routing.
\end{enumerate}

\section{Discussion and Limitations}
\label{sec:discussion}
Key system strengths include fast execution, load-balanced stability, and robust frustum geometry optimization.

However, several limitations exist:
\begin{enumerate}[leftmargin=*]
    \item \textbf{DEM Spatial Resolution}: The 30m SRTM grid resolution smooths out micro-relief features under $30\text{ m}$. Incorporating 1m LiDAR DEMs would improve micro-catchment precision.
    \item \textbf{Soil Curve Number Uniformity}: The current model assumes a default Curve Number ($CN = 75$, AMC II) across the catchment. Spatially variable soil hydrologic group mapping (HSG A/B/C/D) would refine runoff estimates.
    \item \textbf{Static Rainfall Averages}: Long-term annual averages do not account for intra-seasonal dry spells or extreme 24-hour storm events.
\end{enumerate}
